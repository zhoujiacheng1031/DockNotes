# DockNotes v0.9 — 工作区标签组

## 1. 目标

让用户把侧边便签按工作、生活、项目等场景组织为多个工作区，并能即时切换整组侧边标签，同时保持 DockNotes 现有的直接、轻量和可靠体验。

工作区是一组侧边标签，不是多层文件夹，也不是普通关键词标签。v0.9 优先建立清晰、稳定的一对一归属模型，为后续智能工作区和应用关联规则保留扩展空间。

## 2. 产品边界

### 2.1 v0.9 包含

- 每个便签属于且只属于一个工作区。
- 首次升级自动创建“默认工作区”，现有便签全部迁入，原顺序不变。
- 侧边栏一次只展示当前工作区的便签标签。
- 工作区可新建、改名、选择颜色、排序和删除。
- 便签支持组内拖动排序、跨工作区拖动，以及菜单移动。
- 便签库支持按工作区浏览、搜索、筛选和批量移动。
- 当前工作区和各工作区内的标签顺序跨重启保存。
- 前九个工作区支持 `⌥⌘1…9` 快速切换。

### 2.2 v0.9 不包含

- 嵌套工作区或文件夹树。
- 一张便签同时属于多个工作区。
- 根据日期、标题或任务状态自动生成的智能工作区。
- 根据当前前台应用自动切换工作区。
- 云端多人共享工作区。

这些能力只能在基础模型稳定后单独设计，不能通过临时字段或隐式规则提前混入 v0.9。

## 3. 核心行为

### 3.1 工作区切换

- 侧边标签控制区显示紧凑的工作区胶囊：颜色、名称缩写和展开入口。
- 点击胶囊打开工作区列表，展示名称、颜色、便签数量和当前选中状态。
- 切换时收起当前侧边编辑器，然后立即替换整组标签，不自动打开新工作区中的便签。
- 每个工作区记住最后活动便签，用于后续快捷操作，但切换时不强制展开。
- 工作区切换不改变任何便签的置顶、任务、提醒或归档事实。

### 3.2 标签拖动

- 当前的直接拖动继续负责工作区内排序，手势、阈值和动画保持一致。
- 拖动标签进入工作区胶囊区域后立即展开目标列表，不要求长按，不切换成低效率的“手形等待”交互。
- 悬停目标工作区即可预览投放位置，松开后移动并追加到该工作区末尾。
- 右键菜单和便签库提供“移到工作区”，作为精确、可访问的替代方式。
- 拖动取消、窗口失焦或指针释放异常时，标签必须回到原位置且之后仍可继续拖动。

### 3.3 展开便签与桌面便签

- 切换工作区时，侧边展开的便签收起；原工作区顺序和最后活动便签保持。
- 已脱离侧边栏的桌面便签继续显示，不随工作区切换消失。
- 桌面便签仍保留原工作区归属；收回侧边栏时回到该工作区。
- 若收回的便签不属于当前工作区，不强制切换工作区，只更新其归属工作区的标签集合。

### 3.4 新建与快速记录

- 侧边栏、菜单栏和全局快捷键新建的便签进入当前工作区。
- 便签库处于某一工作区范围时，新建便签进入该工作区；处于“全部工作区”时进入当前工作区。
- 快速记录保存后进入当前工作区，并延续现有的立即保存与侧边可见行为。

### 3.5 删除工作区

- 至少保留一个工作区。
- 删除非空工作区不会删除任何便签，而是把其中便签按原顺序移入“默认工作区”。
- 删除默认工作区前必须先指定新的默认工作区；v0.9 可直接禁止删除默认工作区以降低误操作风险。
- 工作区删除提供短时撤销；撤销恢复工作区身份、颜色、顺序和便签归属。

## 4. 全局能力保持独立

- 任务中心默认继续汇总全部工作区，避免切换工作区后漏掉待办。
- 通知提醒、每日摘要和系统日历同步继续读取全部未归档便签。
- 归档便签保留原工作区归属，恢复后回到原工作区；若原工作区已删除，则进入默认工作区。
- 搜索支持“当前工作区”和“全部工作区”两种明确范围。
- AI、导入导出和 Obsidian 备份不得因工作区引入隐式过滤，除非界面明确显示当前导出范围。

## 5. 数据模型与迁移

### 5.1 新模型

```swift
struct NoteWorkspace: Identifiable, Codable, Equatable, Sendable {
    var id: UUID
    var name: String
    var colorHex: String
    var createdAt: Date
}

struct DockNotesDocument: Codable {
    var schemaVersion: Int
    var activeWorkspaceID: UUID
    var defaultWorkspaceID: UUID
    var workspaces: [NoteWorkspace]
    var notes: [DockNote]
}
```

`DockNote` 新增可迁移字段：

```swift
var workspaceID: UUID?
```

工作区顺序使用 `workspaces` 数组顺序；标签顺序继续使用 `notes` 数组的相对顺序。这样不再引入第二套 `noteIDs` 排序表，避免两个来源发生失配。

### 5.2 文件迁移

- 新文件使用带 `schemaVersion` 的 `DockNotesDocument` 容器。
- 启动时先尝试解码新容器；失败后兼容解码旧 `[DockNote]` 数组。
- 旧数据迁移时生成稳定的默认工作区，将所有活动与归档便签归入该工作区，并保持数组顺序。
- 完成迁移后使用现有原子写入和 `.backup` 机制保存；不得先覆盖唯一可恢复副本。
- 对缺失、失效或已删除的 `workspaceID`，统一修复到默认工作区并记录自检状态。

## 6. Store 与模块边界

`NotesStore` 负责工作区事实和原子持久化：

- `workspaces`
- `activeWorkspaceID`
- `defaultWorkspaceID`
- `activeWorkspaceNotes`
- `createWorkspace`
- `renameWorkspace`
- `moveWorkspace`
- `deleteWorkspace`
- `undoWorkspaceDeletion`
- `moveNote(_:toWorkspace:)`
- `moveNote(_:toWorkspace:at:)`

`DeckLayout` 不感知工作区规则，只接收已经过滤好的当前工作区便签，从而保持布局模块纯净。

`PanelCoordinator` 只处理切换时的窗口表现：收起旧的侧边编辑器、刷新 Deck、保留桌面便签窗口。

任务、提醒和日历协调器继续读取 `store.notes` 全集，不改为 `activeWorkspaceNotes`。

## 7. 界面方案

### 7.1 侧边标签

- 工作区胶囊放在现有标签堆叠与新增按钮之间或控制区顶部，不占用标签槽位。
- 使用当前纸张渐变体系的低饱和颜色标识工作区，不把它设计成另一张便签标签。
- 弹出面板宽度约 220–260 pt，包含工作区列表、新建和管理入口。
- 空工作区显示轻量空状态及“新建便签”，屏幕边缘唤起区域仍保持 2 pt。

### 7.2 便签库

- 顶部增加范围选择：“全部工作区 / 当前工作区”。
- 筛选行增加工作区下拉菜单，不再增加新的永久侧栏层级。
- 列表行可显示小型工作区色点；批量操作支持移动到目标工作区。
- 工作区管理使用独立 sheet：名称、颜色、排序、便签数量和安全删除。

### 7.3 菜单与快捷键

- 状态栏菜单显示当前工作区，并提供切换子菜单。
- `⌥⌘1…9` 对应前九个工作区。
- 便签上下文菜单提供“移到工作区”。
- 所有入口使用同一 Store 操作，避免侧边栏和便签库产生不同结果。

## 9. 自动化验收

- 旧 `[DockNote]` 文件迁移后便签数量、ID、内容、归档状态和顺序完全一致。
- 当前工作区、默认工作区、工作区排序和便签归属跨重启保持。
- 连续切换工作区 100 次，不丢标签、不误开便签、不留下不可交互窗口。
- 每个工作区连续拖动排序 100 次后仍可继续拖动。
- 跨组移动后，源组、目标组、溢出数量和活动便签状态立即正确。
- 切换左右屏幕边缘后，工作区入口和标签在同一帧完成定位。
- 删除非空工作区不删除便签；撤销后恢复原工作区和归属。
- 归档、恢复、删除、撤销删除和导入便签保持正确工作区。
- 桌面便签在切换工作区后继续显示，收回时进入原工作区。
- 任务中心、提醒和系统日历始终覆盖全部工作区，不重复、不遗漏。
- 工作区为空、只有一个、超过九个，以及当前工作区标签溢出时都有正确界面。

## 10. 完成定义

- 所有 v0.9 范围内行为均有明确数据来源和自动化回归。
- 旧数据迁移可回滚，没有便签丢失或顺序破坏。
- 工作区切换与标签拖动保持即时、流畅，不引入长按等待。
- 现有侧边标签、桌面便签、任务、提醒和日历能力无回归。
