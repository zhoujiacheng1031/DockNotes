# DockNotes v0.4 实施计划

状态：发布候选已完成，等待实体键盘快捷键确认

制定日期：2026-09-22

版本主题：先把核心交互做稳，再扩展能力

当前进度（2026-09-22）：Epic 1–5 已实现并进入最终应用构建。完整自检、原生交互回归、全局快捷键注册与 Carbon 回调派发、Release 构建、差异检查均通过；便签库的筛选、排序、预览以及已归档空状态已在真实应用中完成视觉与操作走查。由于桌面自动化生成的合成按键不会进入 Carbon 全局热键通道，发布前仅剩一次实体键盘 `⇧⌘Space` 跨应用唤起确认。

## 1. 版本目标

v0.4 聚焦日常使用中最频繁、最影响信任感的五项能力：

1. 收敛侧边标签的交互状态，保证拖动、展开、收起、置顶、桌面便签和左右侧切换长期稳定。
2. 增加全局快捷记录，让用户在任何应用中都能立即创建便签。
3. 删除后提供短时撤销，降低误操作成本。
4. 显示真实保存状态，并具备写入失败与异常退出恢复能力。
5. 强化便签库的查找、筛选、排序和预览效率。

本版本的成功标准不是功能数量，而是“连续使用时不会失灵、不会丢内容、不会让用户猜测当前状态”。

## 2. 范围与非目标

### 本版本范围

- Edge Deck 统一状态流转与交互回归测试
- 全局快捷键与快速记录窗口
- 删除撤销
- 自动保存状态、失败提示与恢复
- 便签库常用筛选、排序和快速预览

### 本版本暂不包含

- 新增 AI 能力或更换 AI 工作流
- 多人协作、云同步和账号系统
- 完整回收站
- 工作区分组、应用关联便签
- 完整版本历史
- 重做视觉主题或大规模信息架构调整

以上能力进入 v0.5 以后评估，避免与核心稳定性改造并行扩大风险。

## 3. 实施顺序

### 批次 A：核心可靠性

依次完成：

1. Edge Deck 状态收敛
2. 保存状态与恢复
3. 删除撤销

这三项共同决定用户是否敢把 DockNotes 当作长期使用的记录工具，应当作为 v0.4.0 首批发布内容。

### 批次 B：日常效率

依次完成：

1. 全局快速记录
2. 便签库筛选、排序和预览

这两项建立在批次 A 的状态与持久化行为稳定之后，作为 v0.4.0 后半段完成。

## 4. Epic 1：Edge Deck 状态收敛

### 用户结果

侧边标签无论连续操作多少次，都能立即响应；拖动时随鼠标移动并自然换位；展开、收起、置顶、桌面便签及左右侧切换不会互相破坏。

### 实施方向

- 建立单一的状态变更入口，所有点击、悬停、拖动、失焦、置顶和屏幕变化事件通过同一套转换规则处理。
- 明确区分视觉状态与持久状态：
  - 视觉状态：收起、展开、拖动中、换位动画中。
  - 便签状态：当前打开、置顶、桌面便签、归档。
- 拖动会话以明确的开始、更新、结束、取消生命周期管理；任何结束路径都必须清理捕获状态。
- 标签换位以指针越过相邻标签中心线为准，动画只表现最终排序，不阻断后续指针事件。
- 切换左右侧时立即重新计算窗口与命中区域，不依赖下一次点击刷新。
- 应用失焦只影响未置顶标签的展开状态，不改变置顶事实，也不从侧边列表移除当前便签。
- 桌面便签的书脊和顶部标题区均可直接拖动窗口；正文编辑区保持文本选择能力。

### 验收标准

- 连续拖动并换位 100 次，标签始终跟手，之后仍可继续拖动。
- 单击任意标签均能一次打开，不需要先收起再展开。
- 打开标签后点击桌面，标签仍保留在侧边列表；再次展开时顺序不变。
- 置顶标签点击桌面后仍保持可见与置顶，不发生“状态显示置顶但窗口已收起”。
- 在收起、展开、打开便签三种状态下切换左右侧，界面立即移动，边缘唤起无需额外点击。
- 拖动取消、切换窗口、按 Esc、应用失焦后，下一次拖动均正常。
- 桌面便签可从左侧书脊和顶部区域移动，移动过程无明显跳动。

### 测试要求

- 为状态转换增加单元测试，覆盖合法转换、重复事件和取消路径。
- 为拖动排序增加坐标边界、快速往返和连续 100 次压力测试。
- 在左侧、右侧和不同屏幕尺寸下完成手动回归。

## 5. Epic 2：真实保存状态与恢复

### 用户结果

用户能明确知道内容正在保存、已经保存或保存失败；应用异常退出后，已输入内容可以恢复。

### 实施方向

- 使用统一保存状态：`正在保存`、`已保存`、`保存失败`。
- 编辑后短延迟自动保存，频繁输入合并写入，停止输入后尽快落盘。
- 文件写入采用临时文件加原子替换，保留最近一次有效快照。
- 保存失败时保留内存中的最新内容，显示可重试提示，不用成功文案覆盖失败状态。
- 启动时发现未完成写入或恢复快照时，优先恢复较新的有效内容并提示用户。

### 验收标准

- 输入后 300 毫秒内进入“正在保存”，成功落盘后显示“已保存”。
- 模拟不可写目录或写入错误时显示“保存失败”，内容不会从编辑器中消失。
- 强制终止应用后重启，最后一次已确认保存的内容完整存在。
- 快速连续输入、切换标签和关闭窗口不会写入旧内容覆盖新内容。
- 更新应用后现有便签与设置保持兼容，不要求重新配置。

### 测试要求

- 覆盖保存去抖、并发保存顺序、失败重试、损坏文件和恢复快照。
- 对旧版本数据执行一次真实升级回归。

## 6. Epic 3：删除撤销

### 用户结果

误删便签后可立即撤销，正常删除动作不再带来不可恢复的焦虑。

### 实施方向

- 删除后在界面底部显示 10 秒撤销提示。
- 撤销期间保留便签内容、原排序位置及关键状态，不立即永久清理。
- 撤销后恢复原位置；超时后再提交最终删除。
- 连续删除时提示区显示最近一项，并维护可预测的待删除队列。
- 归档与删除保持不同语义，归档不触发删除撤销。

### 验收标准

- 删除后列表立即更新，10 秒内点击撤销可完整恢复内容与原位置。
- 从侧边标签、便签库和编辑窗口删除，撤销行为一致。
- 删除当前打开、置顶或桌面便签时，不遗留空窗口或无效状态。
- 连续删除多个便签后逐项撤销或超时，数据结果正确。
- 应用在撤销倒计时中退出时，不产生幽灵便签或重复便签。

## 7. Epic 4：全局快速记录

### 用户结果

用户在任何应用中按一次快捷键即可开始记录，保存后可立即返回原来的工作。

### 实施方向

- 默认快捷键：`⇧⌘Space` 打开快速记录，`⌥⌘N` 直接新建便签。
- 设置中允许修改快捷键，并检测与系统或应用快捷键冲突。
- 快速记录窗口默认聚焦正文，支持键盘完成保存和关闭。
- 新建便签保存后进入 Edge Deck，并遵循现有排序规则。
- 快速记录调用统一保存流程，不另建一套持久化逻辑。

### 验收标准

- DockNotes 在后台或无窗口时，快捷键仍能唤起快速记录。
- 从按键到光标可输入的时间在正常设备上不超过 300 毫秒。
- `⌘Return` 保存并关闭，`Esc` 取消；取消空白便签不会生成垃圾记录。
- 快捷键冲突时给出明确提示，不能悄然注册失败。
- 保存后便签立即出现在侧边标签和便签库中。

## 8. Epic 5：便签库效率升级

### 用户结果

便签数量增多后，用户仍能快速找到当前要处理的内容，而不必依赖记忆或逐条打开。

### 本期功能

- 排序：最近修改、最早到期、最新创建。
- 筛选：全部、置顶、未完成待办、已逾期、已归档。
- 保持标题区、分类切换和搜索栏固定在顶部，仅内容列表滚动。
- 单击列表项显示轻量预览，双击或明确操作进入完整编辑。
- 搜索同时匹配标题、正文与待办文字，并与筛选条件组合。

### 验收标准

- 切换全部与已归档时，标题、分类和搜索栏位置不移动。
- 排序或筛选后打开、归档、恢复和删除便签，列表立即正确更新。
- 搜索与筛选组合使用时结果准确，清空搜索后保留当前筛选条件。
- 预览不会改变侧边标签的打开、置顶或排序状态。
- 使用键盘可在搜索框、筛选项、列表和预览之间移动并执行主要操作。

## 9. 发布门槛

v0.4 只有同时满足以下条件才可发布：

- 所有现有自检通过，并新增上述状态、保存和撤销测试。
- `git diff --check` 无格式问题，Release 构建成功。
- 完成一次真实应用手动验收：左右侧切换、100 次拖动、置顶失焦、桌面便签移动、保存失败、删除撤销、全局快捷记录、便签库筛选。
- 不破坏旧版便签、设置和 AI 配置。
- 没有已知的数据丢失、无法打开标签或拖动失效问题。

## 10. 建议提交拆分

每一项保持可独立验证和回滚：

1. `refactor: centralize edge deck transitions`
2. `test: add edge deck interaction stress coverage`
3. `feat: expose durable note save states`
4. `feat: add undoable note deletion`
5. `feat: add global quick capture shortcuts`
6. `feat: add library filters sorting and preview`
7. `test: add v0.4 release regression coverage`

## 11. 后续候选

v0.4 稳定后，优先评估：

1. 今日、即将到期和逾期任务视图
2. Markdown/TXT 导入导出
3. 自定义命令面板与完整快捷键体系
4. 便签版本历史
5. AI 结构化操作、修改预览和隐私范围
6. 应用关联便签与工作区分组

这些候选在进入开发前应分别确认用户场景，不与 v0.4 核心可靠性工作混合。
